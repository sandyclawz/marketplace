# Предсказание покупки в течение 90 дней

Модель бинарной классификации, которая для клиентов интернет-магазина одежды оценивает
вероятность покупки в ближайшие 90 дней. Цель — приоритизировать рассылки на пользователей,
готовых совершить покупку. Целевая метрика — **ROC-AUC**.

## Результат

| Модель | ROC-AUC (hold-out) |
|---|---|
| Логистическая регрессия | 0.767 |
| Градиентный бустинг (HistGradientBoosting) | 0.768 |
| **Ансамбль (ранговое усреднение)** | **0.775** |

Кросс-валидация (5 фолдов) на обучающей выборке: ROC-AUC ≈ 0.76.

## Данные

Ожидаются CSV-файлы в одной папке (путь задаётся переменной `DATA_DIR` в ноутбуке):

- `apparel-purchases.csv` — история покупок (клиент, цена, количество, `category_ids`, дата);
- `apparel-messages.csv` — история рассылок (событие, канал, дата); ~1.4 ГБ, читается чанками;
- `apparel-target_binary.csv` — целевая метка `target`;
- `full_campaign_daily_event*.csv` — агрегаты кампаний (в текущем решении не используются,
  оставлены как задел для улучшений).

## Подход

1. **Временна́я граница.** История заканчивается 2024-02-16; целевое окно (следующие 90 дней)
   в данные не входит. За точку среза берём последнюю дату, признаки считаем строго до неё —
   утечки будущего нет.
2. **Признаки по покупкам:** RFM (recency / frequency / monetary), активность в окнах
   30/90/180/365 дней, средний интервал между покупками, тренд последних 90 дней.
3. **Категории:** `category_ids` — вложенный список со сквозной нумерацией и меняющейся
   глубиной. Признаки строятся по присутствию id (число различных категорий, покупки по
   топ-уровневым категориям), а не по позиции в списке — это устойчиво к обновлениям дерева
   категорий и к маркерам распродажи/пола в начале списка.
4. **Признаки по рассылкам:** счётчики событий, open/click-rate, давность последнего
   события/открытия/клика, активность за 90 дней, доля email против push.
5. **Модели:** логистическая регрессия (бейзлайн) и градиентный бустинг с тюнингом; финал —
   их ранговое усреднение. Дисбаланс классов (~1.9% позитивов) учтён через
   `class_weight="balanced"` и метрику ROC-AUC.

Наибольший вклад дают признаки вовлечённости в рассылки (давность последнего клика, клики за
90 дней) и истории покупок (срок жизни клиента, recency, средний чек).

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
jupyter lab                                          # открыть solution.ipynb
```

В ноутбуке `solution.ipynb` задайте `DATA_DIR` — путь к папке с CSV — и выполните все ячейки
сверху вниз. Ноутбук самодостаточен: строит признаки, обучает и тестирует модель.

## Состав репозитория

- `solution.ipynb` — полное решение: EDA, признаки, обучение, тюнинг, тестирование;
- `README.md` — этот файл;
- `requirements.txt` — зависимости.

## Возможные улучшения

Признаки из агрегатов кампаний `full_campaign_daily_event*` (средний open/click-rate кампаний,
в которых участвовал клиент), сезонность покупок, эмбеддинги категорий, калибровка
вероятностей, отбор признаков.
