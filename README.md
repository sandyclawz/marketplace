# Предсказание покупки в течение 90 дней

Исправленная версия проекта по замечаниям ревью v1. Целевая метрика — ROC-AUC.

## Результат исправленного запуска

**Результат.** По среднему train CV выбрана **Ensemble** (ROC-AUC 0.7683, стандартное отклонение 0.0148). На ранее просматривавшемся hold-out: **ROC-AUC 0.7714**. Первые пять признаков по CV permutation importance: `m_last_click_days`, `p_avg_amount`, `p_spend_last_180`, `p_cat_4_share`, `m_click_90`. **Топ-10%** охватывает 42.2% покупателей при precision 8.1%; lift **4.22**. **Топ-20%** охватывает 57.8% покупателей при precision 5.6%; lift **2.89**. 

## Что исправлено

- Проведён EDA покупок и всех 12 739 798 событий рассылок: пропуски, полные совпадения строк,
  распределения, цены, количества, число строк и дней покупок на клиента, события и каналы.
- Проверены обе таблицы агрегатов кампаний: данные в них доходят до 15.05.2024.
  Полные итоги исключены из модели как потенциальный источник утечки.
- Исправлено утверждение о датах: покупки до 16.02.2024, рассылки до 15.02.2024.
  Срез — 16.02.2024, последний день рассылок неизвестен; разрыв покрытия проверяется.
- Совпадающие покупки сохранены: без order_id/product_id нельзя отделить повтор выгрузки
  от одинаковых товарных позиций. Счётчики названы числом строк, не числом заказов.
  Аналогично журнал рассылок сохраняет регистрации событий; политика и ограничения объяснены в EDA.
- Убраны нули вместо неизвестного интервала и значения 9999 вместо неизвестной давности.
  HGB использует NaN, логрегрессия — импутацию внутри pipeline с индикаторами пропусков.
- Категории выбираются воспроизводимо по train, добавлены доли категорий и отношение активности окон.
- Варианты логрегрессии с log1p и без него сравниваются на одинаковых train CV фолдах.
- Выбор одиночной модели или ансамбля перенесён на OOF-предсказания train.
  В исправленном процессе тест применяется только для оценки выбранного варианта.
- Важность выбранной модели и диагностика одиночных признаков считаются на train/валидации.
- Добавлены recall, precision и lift для топ-10%/20%; выводы формируются из результатов запуска.
- Исходные комментарии ревьюера сохранены. После замечаний добавлены отдельные синие ответы автора.

## Запуск

1. Установить зависимости: `pip install -r requirements.txt`.
2. Поместить CSV в `filtered_data` рядом с ноутбуком или задать переменную окружения `DATA_DIR`.
3. Запустить Jupyter из папки проекта, открыть `solution.ipynb` и выполнить ячейки сверху вниз.

Нужны все пять файлов:

- apparel-purchases.csv
- apparel-messages.csv
- apparel-target_binary.csv
- full_campaign_daily_event.csv
- full_campaign_daily_event_channel.csv

## Проверка

Ноутбук выполнен целиком на исходных CSV без ошибок. Дополнительно проверены отсечение будущих
событий, NaN при одном дне покупок, доли категорий, совпадение результатов агрегации рассылок
при разных размерах чанка и индикаторы отсутствующих событий. Структура ноутбука проверена
через nbformat, исходные комментарии ревьюера сверены с v1 без изменений.

Окружение проверки: Python 3.13; Python-пакеты: numpy 2.5.3; pandas 3.0.6; scikit-learn 1.9.1; scipy 1.18.1; matplotlib 3.11.2.
